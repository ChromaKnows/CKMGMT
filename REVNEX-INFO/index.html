Rule: no destructive cleanup should be performed without reviewing exactly what will be removed.

LatencyMon Findings

Real-time audio diagnostics
Primary finding
ACPI.sys was the dominant DPC outlier.
This points toward Windows/firmware power-management behavior rather than a direct failure of the Apollo USB audio driver.
Network comparison
Disabling networking materially reduced background latency/page-fault noise, but the ACPI DPC spike remained. Networking was therefore treated as a secondary contributor rather than the root cause.
Because real Ableton playback is currently stable, risky BIOS or power-management changes were intentionally deferred. Revisit only if a repeatable real-world audio problem appears.

Changes Made

iLok / PACE

Startup dependency corrected
Resolved
The PACE licensing service had been disabled/stopped. It was changed to start automatically and is now running. This should reduce the need to manually launch iLok License Manager before opening projects with protected plug-ins.
No license data was removed or changed.

Daily Startup & Recovery Procedure

Fast reference
Normal cold start
Power/connect the Apollo.
Start Windows and let services finish loading.
Open UAD Console once if monitoring/input is not active.
Open Ableton using the known-good audio configuration.
If Apollo is not recognized after restart
Let Windows finish loading.
Power-cycle Apollo.Off → wait a few seconds → on.
Open UAD Console once.
Test mic + headphones before opening the project.

Diagnostic Tools

Use only when needed
HWiNFO64
Use for CPU temperatures, clocks, throttling, memory, GPU, drive temperatures, and hardware-error indicators.
Use it when: fan behavior changes, performance drops, the machine feels unusually hot, or after hardware maintenance.
LatencyMon
Use to investigate DPC/ISR latency, driver interference, and hard page faults that can cause pops, clicks, stutters, or dropouts.
Use it when: audio suddenly becomes unstable, after major driver/Windows changes, or when qualifying another production machine.

Pressure-Test Checklist

Real-world validation
Open several of the largest normal production projects.
Produce normally for 30–60 minutes.
Watch for repeatable symptoms.Dropouts, crackles, UAD disconnects, licensing errors, unusual fan behavior, or project-specific CPU spikes.
Use diagnostics only if a symptom appears.HWiNFO for thermal/power behavior; LatencyMon for driver/DPC behavior.
Success criteria
  • Heavy projects remain clean at 48 kHz / 1024 / USB Safeguard ON.
  • No manual iLok launch is required.
  • Apollo remains stable for full sessions.
  • No new thermal-throttling behavior.
  • No repeatable dropouts during normal production.
If these stay true: stop optimizing. The workstation is doing its job.
